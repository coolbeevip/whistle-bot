# ESP32 Android 应用验收

## 浏览器回归测试

在开发机安装 Node.js 22，从仓库根目录执行以下命令。GitHub Actions 在每次推送和拉取请求时运行同一套测试。

```sh
cd esp32-android
npm ci
npx playwright install chromium
npm test
```

测试用 Chromium 以手机视口通过本地 HTTP 服务加载控制台资源，通过触摸和表单操作页面。WebSocket 对端模拟控制器，测试检查实际发出的协议消息以及页面收到遥测后的状态变化。已安装 Google Chrome 的开发机也可以运行 `CHROME_CHANNEL=chrome npm test`。

| 页面 | 验收内容 |
| --- | --- |
| 方向键 | 四个触区的左右轮符号、松手、触控取消、失焦和中央 Stop。按住时延迟第一条回执，检查下一窗口仍有续期，松手后无新驱动指令。 |
| 速度 | 四个预设、滑块、两种加速模式。分别核对已标定的 mm/s 指令和基础模式的 ticks/s 指令。 |
| Precision | 前进、后退的米数转换，左右转角的符号，非法目标、未标定禁用、执行中续期、完成及中途 Stop。 |
| Calibration | M3/M4 单轮点动及释放、映射提交与丢弃；距离和角度分别采样、计算、试跑、保存；检查角度采样点动及试跑中断提示。 |
| 状态与设置 | 控制权占用、驱动离线、超时、网页重连、编码器与 PWM 显示、低电量告警、CSV 下载、测试网络扫描与配置、热点恢复页。 |

## 真机验收

在手机上[安装调试 APK](../esp32-android/README.md)，打开 Whistle Bot，连接小车并停在驾驶页。将开启 USB 调试的手机连接电脑，在 `esp32-android/` 中运行以下命令。脚本通过 ADB 连接前台应用的 WebView，检查遥测与页面切换。

```sh
node test/live.cjs
```

**四向动力检查**需要先架空两只驱动轮，接通驱动板电源，并退出其他驾驶会话。显式增加参数后，脚本用 0.2 m/s 档逐一按下四个方向键，根据两轮编码器速度的符号判断方向，每次松手并按 Stop，确认控制权释放、底盘静止且左右 PWM 为零后才继续下一项。

```sh
node test/live.cjs --wheels-lifted
```

**地面精度**需要外部量具。将车放在平整地面，用胶带标出起点与车头方向，分别执行前进和后退 0.25 m、左转和右转 45°。每次从标记处开始，记录实测距离或角度、页面完成状态和偏差，按项目实际精度要求判定。另起一次前进动作，中途按 Stop 并确认停车。重新标定时，用尺量轮胎一周的距离，用地面标记量试转角度，逐项保存并刷新页面核对状态。
