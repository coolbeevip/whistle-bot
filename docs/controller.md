# 控制器构建与调试

正式固件位于 [esp32-s3](../esp32-s3)。在该目录使用 PlatformIO Core。先通过设备列表识别 ESP32 的 UART 下载口，再用实际端口替换示例中的占位符。

```sh
pio run
pio device list
pio run -t upload --upload-port <ESP32串口>
pio device monitor -p <ESP32串口> -b 115200
```

烧录会替换 ESP32 当前程序。下载端口是 ESP32 自身标有 UART 的 USB 口。打开串口监视器后按一次 RESET，启动消息 `wifi_setup` 给出本机热点名称和密码。手机连上该热点后，打开[Android 应用](../esp32-android/README.md)，用控制器地址 `192.168.4.1` 连接。

## 网络设置

小车停稳并释放控制权后，在 Android 应用的 **Settings → Wi-Fi** 点 **Scan**。扫描由 ESP32 执行，结果显示在 **Nearby networks** 下拉框。手机与小车同在局域网时也可以扫描。

要保存新网络，先让手机连接小车自己的热点，并将 **Controller address** 设为 `192.168.4.1`。如果热点已关闭，长按 **BOOT** 5 秒可以恢复热点，已保存的网络凭据和标定会保留。选择目标 2.4 GHz 网络（隐藏网络可直接填写名称），输入密码并点 **Connect & save**。连接成功后，记下页面显示的小车新 IP，将手机切换到目标网络，再用新 IP 连接小车。蓝灯表示热点就绪，绿灯表示已连接家庭网络。

## 驾驶和标定

Android 控制台仅允许竖屏驾驶和标定试跑。驾驶中切到横屏会释放控制权，转回竖屏后需重新操作。

1. 按[参考接线](hardware.md)连接两板，架空车轮并给驱动板供电。确认面板显示底盘在线，左右轮的通道与方向正确。
2. 在 **Settings → Chassis → Chassis calibration** 保存方向映射。距离标定可将车轮向前转一整圈，输入轮周长；参考轮径 67.5 mm 对应约 212 mm。保存后完成距离复测，为轮速控制和距离测量提供尺度。
3. 需要校验有效轮距时，在 **Advanced → Effective track width**输入相对地面参考线量得的实际转角，保存并完成复测，验证编码器推算的有效轮距。重新标定距离后应复测距离与转角。
4. 手动驾驶按住方向键运动，松开即释放控制权。单次定距上限为 3 m，定角上限为 360°。

## 上位机协议

USB 使用每行一个 JSON 对象（115200、8N1），Wi-Fi 使用 `ws://192.168.4.1/ws`（每条文本消息一个对象）。首先发送：

```json
{"v":1,"id":1,"op":"hello"}
```

后续消息填入应答中的数字 `session`，递增 `id`。发送 `status` 查询状态，或发送 `subscribe`、`topic:"encoders"`、`hz:5` 订阅反馈。`claim` 返回数字 `lease` 和 `window`；在持有期间按 `control_window` 事件更新窗口。手动驾驶以 10 Hz 发送 `drive`。定距与定角只提交一次目标并附 `request_key`，随后发 `heartbeat` 续期。两个入口共用驾驶权，手机和 USB 客户端可同时观察。可选雷达适配器接口位于 [lidar.h](../esp32-s3/src/sensors/lidar.h)，默认配置无雷达。

Precision 的 Move 在执行时读取 Joystick 当前档位，通过 `move_distance.speed_mm_s` 传入直行巡航上限（整数 mm/s）。前进和后退都随剩余距离减速。支持此参数的固件在握手时声明 `move_speed`；省略参数时使用原有的 60 mm/s 上限。Turn 使用独立的转向速度曲线。

Android 应用按方向键时随 `claim` 发送 `manual_pad: true`。该控制权只接受手动驾驶及停车操作。控制窗口每 100 ms 更新，续期上限为所用窗口生成后的 450 ms。引用同一窗口不会推迟截止时间，已被更新指令取代的窗口会被拒绝。松手立即请求释放。Precision 随 `claim` 发送 `precision: true`，直行、后退及转向使用相同的 450 ms 窗口。动作运行期间由 `heartbeat` 续期，按 Stop 会立即请求停车。普通 `claim` 和标定仍为 300 ms。

## 驾驶超时记录

板载驾驶 CSV 每约 100 ms 采样一次，停车时再记一行。用 `tools/read_drive_log.py` 下载。新版记录追加以下字段，时间单位为 ESP32 启动后的毫秒。

| 字段 | 含义 |
| --- | --- |
| `queued_window`、`window_open_ms`、`window_queued_ms` | 最近一次成功放入传输队列的控制窗口、生成时间和入队时间 |
| `enqueue_failures` | 本次控制权持有期间，控制窗口因队列不可写或入队失败的累计尝试次数 |
| `drive_window`、`drive_received_ms`、`drive_accepted_ms` | 最近一次交给控制任务的驾驶指令所引用的窗口、完整帧到达传输层的时间，以及控制任务接受时间。接受时间为 0 表示尚无成功指令或该次指令被拒绝 |

比较同一窗口 ID 的入队与收令时间，可估算消息排队、手机处理及返回的总耗时。采样间发生的多次更新只保留最新值。首条指令也可以直接使用领取控制权时返回的窗口。

## Precision 航向控制

将 IMU 固定在底盘上，小车停在水平地面，通电后保持静止约两秒。固件以静止加速度估计竖直方向，估计陀螺仪零偏，将角速度投影到车身竖直轴并按采样时间积分。每个动作从自己的起始航向计角，左转为正。

Precision 和上位机的定距、定角指令均要求 IMU 就绪、距离标定已验证。旋转以陀螺仪实测角度减速、停车和确认到位；直行及后退按左右编码器平均行程停车，以航向偏差和角速度调节左右轮速。控制台显示相对起始方向的 Yaw。传感器掉线、样本超过 100 ms 或角速度饱和会中止当前动作，恢复后需重新静止估计零偏。方向键保留原有的编码器控制，标定试跑仍用于检验编码器几何参数。

转向按朝向目标的实测角速度预估滑行角，初始提前量取 0.10 秒。进入停车阶段后，控制器在编码器停稳且连续 150 ms 的陀螺仪样本低于 3°/s 时检查角度。停在容差外最多再做两次低速修正。实车调试时，分别用地面标线测量左右转的最终角度，同时记录 App 显示的动作编号、目标角、Yaw 和结束原因。

同一次开机内可向 `status` 附加 `action_id` 或原始 `request_key`，查询最近 16 次动作之一。转向结果中的 `brake_yaw_deg` 和 `brake_rate_dps` 是首次下发零速时的航向变化和角速度。`coast_deg` 是此后到首次确认停稳的有符号角度变化，`brake_to_confirmed_rest_ms` 包含停稳确认窗口。提前取消时，`action_yaw_deg` 是动作结束时最新的有效估计，结束原因保存在 `action_reason` 中。
